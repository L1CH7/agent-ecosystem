# MCP Google Search Grounding — Руководство и регламент для AI-агентов

## 1. Архитектура и принцип работы («В чем соль»)
Инструменты `google_search` и `google_search_batch` для моделей семейства Gemini обращаются напрямую к нативному эндпоинту Antigravity Manager:
**`/v1beta/models/{target_model}:generateContent`** с моделью **`gemini-3.8-flash-tiered`** (для сторонних моделей используется совместимый роут `/v1/chat/completions`).

Это **НЕ** примитивный HTTP-запрос к поисковому API со списком ссылок и сниппетов. На бэкенде работает рассуждающая модель Gemini 3.8 с активным Search Grounding:
1. Модель читает ваш инженерный контекст и формулирует исследовательские гипотезы.
2. Модель самостоятельно формирует серию точечных подзапросов в Google (multi-hop retrieval).
3. Модель анализирует найденные страницы, сопоставляет факты, фильтрует устаревшую информацию и синтезирует глубокий аналитический ответ с цитатами.
4. Внутренние блоки размышлений (`thought: true`) потоково пишутся в хранилище мыслей — вызывающий агент получает чистый структурированный синтез.

---

## 2. Приоритет MCP Google Search над стоковыми поисковиками
- Стоковые утилиты типа `search_web` возвращают короткие поверхностные фрагменты текста без глубокого анализа страниц и часто упираются в поисковый шум.
- Для любых исследовательских задач, поиска скрытых связей, верификации фактов, поиска по реестрам, патентам и профилям **ОБЯЗАТЕЛЬНО** использовать инструмент `call_mcp_tool` (сервер `google-search`, методы `google_search` и `google_search_batch`).

---

## 3. Как формулировать запросы (Антипаттерны и Рекомендации)

### ⛔ СТРОГО ЗАПРЕЩЕНО (Типичные ошибки агентов):
- **Использовать синтаксис поисковой строки 2005 года**: кавычки для точного совпадения, операторы `OR`, `AND`, `NOT`, `site:`, `inurl:`.
  - *ПРИМЕР ОШИБКИ*: `"\"vision in the loop\" LLM VLM CFD verification OR \"agentic CFD validation\""`.
- **Сваливать несвязанные темы в один запрос через `OR`**: Если вам нужно 3–5 разных аспектов — **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** склеивать их в один запрос. Для этого существует инструмент `google_search_batch`.
- **Писать облако ключевых слов через запятую или пробел**.

### ✅ ОБЯЗАТЕЛЬНО (Корректный подход):
- Писать развернутую исследовательскую или инженерную постановку задачи на естественном русском или английском языке.
- Описывать предмет поиска, контекст, предполагаемые ведомства, организации, предметную область.
- Формулировать конкретные критерии приемки: какие именно атрибуты, факты, цитаты или первоисточники требуется найти.

## 4. Время выполнения и нормальная задержка (60–120 секунд)
- **Многошаговое рассуждение**: Поскольку на бэкенде выполняется автономный исследовательский цикл (поиск $\to$ чтение $\to$ уточняющий поиск $\to$ анализ глубоких карточек), запрос объективно занимает от **45 до 120 секунд**.
- **Это НЕ зависание!** Агент обязан терпеливо дожидаться ответа инструмента и не обрывать сессию.
- Сервер оснащен сторожевым таймером: если модель активно рассуждает в хранилище мыслей, запрос исполняется вплоть до безопасного предела (150 секунд). Если наступает реальная тишина в сети (>40с), сервер изолирует проблемный подзапрос с понятным статусом.

---

## 5. Пакетный поиск (`google_search_batch`)
Если требуется исследовать несколько граней задачи, **строго обязательно использовать `google_search_batch`**:
- **Параллелизм сессий**: Все запросы из массива выполняются одновременно в независимых асинхронных сессиях.
- **Изоляция тем (Zero Context Drift)**:
  Каждый элемент массива должен отвечать за отдельную грань задачи:
  - *Запрос 1*: Официальные реестры (патенты, свидетельства на программы для ЭВМ, лицензии);
  - *Запрос 2*: Отраслевые комитеты, ассоциации, стандарты и экспертные комиссии;
  - *Запрос 3*: Публичные выступления, конференции, доклады и пресс-релизы;
  - *Запрос 4*: Профильные форумы, каналы разработки и сообщества.
- **Частичный возврат данных**: Если один из 4 запросов затянется по таймауту, остальные 3 успешно вернут полные данные.

## 6. Локальная библиотека отчетов и подпроекты (`project`)
- **Именованные отчеты вместо безымянных файлов:** Каждый успешный аналитический синтез Google Grounding сохраняется на диск не как `output.txt`, а в виде структурированного Markdown-файла с человекочитаемым именем по теме:
  `/var/tmp/scratch/google_library/reports/{project}/{YYYY-MM-DD}_{slug}.md`.
- **Поддержка подпроектов (`project`):** Для изоляции исследований передавайте параметр `project` (например, `project="gzla-cfd"`, `project="plasma-article"` или `project="default"`).
- **Полнотекстовый поиск без ожидания (FTS5 / BM25):**
  Инструмент **`google_library_search(query, project=None, limit=5)`** выполняет мгновенный локальный поиск (0.5 мс) по всей базе ранее сохраненных отчетов без обращения к сети и без ожидания рассуждений.
  *Перед запуском тяжелого поиска на 60–120 секунд проверьте библиотеку через `google_library_search`!*
- **Статус библиотеки:** инструмент `google_library_status()` возвращает количество отчетов и активных подпроектов.

## 7. Отказоустойчивость, автофоллбэк и дисциплина агента

### 🛡️ Автоматический перебор моделей (Dual-Stage Fallback)
Сервер автоматически пробует выполнить исследование на **`gemini-3.8-flash-tiered`**. Если шлюз возвращает ошибку или истекает таймаут (140с), сервер прозрачно повторяет запрос на резервной модели **`gemini-3.8-flash-high`**.

### ⛔ ЖЕЛЕЗНЫЕ ЗАПРЕТЫ ДЛЯ АГЕНТА:
1. **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО открывать и читать `server.py`:**
   Все параметры, типы и поведение сервера полностью задокументированы в данной инструкции. Чтение `server.py` тратит драгоценный контекст агента и запрещено регламентом платформы.
2. **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО переключаться на стоковый `search_web`:**
   Встроенный поисковый инструмент Antigravity `search_web` выдает нерелевантный шум и обрезанные сниппеты без анализа первоисточников.
3. **Что делать при временном отказе шлюза Google:**
   - Обратиться к мгновенному сверхбыстрому семантическому поиску **`exa_search` / `exa_search_batch`** (MCP-сервер `exa-search`);
   - Либо извлечь фактуру из локальной базы знаний через **`google_library_search`** или **`exa_library_search`**.

## 8. Проверка доступности (`check_model_liveness`)
Если требуется мгновенно проверить, отвечает ли локальный шлюз модели и активен ли генератор рассуждений, вызовите:
- `call_mcp_tool` с `ServerName="google-search"`, `ToolName="check_model_liveness"`.
- Метод возвращает статус соединения, время отклика шлюза и активные модели.
