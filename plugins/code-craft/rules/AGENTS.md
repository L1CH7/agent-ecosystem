# Регламент инженерии кода и вычислительных систем (Code Craft)

## 1. Протокол контрольных точек VibeWise («Человек проектирует — AI кодит»)
- **Принцип совместного проектирования:**  
  Перед реализацией сложной фичи или рефакторингом агент обязан согласовать архитектуру через контрольные точки:
  1. **Build Checkpoint (Анализ подхода):** Агент выявляет неоднозначности и спрашивает выбор пользователя по структуре данных и граничным условиям, а не решает за него.
  2. **Design Checkpoint (Утверждение схемы):** Краткая фиксация выбранного дизайна («храним так, связываем через это»). Код на этом этапе **не пишется**.
  3. **Implementation Checkpoint (Авторизация правок):** Перечень файлов и тестов, которые будут изменены. Агент пишет код строго после авторизации.
  4. **Implementation Report (Доказательный отчет):** Что изменено, почему это соответствует принятому решению, какие тесты/расчеты запущены и каковы их численные результаты.

## 2. Принцип HERO: Запрет избыточных абстракций (Anti-Overbuild Policy)
- **Категорически запрещено** создавать упреждающие абстракции, промежуточные адаптеры «на будущее», фабрики фабрик и усложненные иерархии классов, если они прямо не запрошены.
- **Минимально достаточная сложность:** Любое архитектурное решение должно быть простейшим из возможных, решающих поставленную задачу сегодня.
- **Сохранение идиоматичности:** Писать код в стиле целевого фреймворка и проекта, а не навязывать универсальные мета-шаблоны.

## 3. Машинный оракул верификации для вычислительных и физических систем
- **Неприменимость примитивных юнит-тестов:**  
  В газодинамике, CFD и математическом моделировании стандартные юнит-тесты на проверку отдельных функций не дают гарантии корректности модели.
- **Обязательные критерии физической состоятельности (Physical Oracle):**
  1. **Инварианты сохранения:** Баланс массы, импульса и полной энергии во всей расчетной области должен сохраняться с точностью до машинного нуля (или консервативного потока схемы);
  2. **Физическая допустимость решения:** Давление $p > 0$, плотность $\rho > 0$, температура $T > 0$. Любое отрицательное значение свидетельствует о дефекте схемы или шага по времени;
  3. **Устойчивость по Куранту (CFL):** Шаг по времени обязан удовлетворять условию Куранта-Фридрихса-Леви ($CFL \le 1.0$ для явных схем);
  4. **Монотонность на ударных волнах:** Отсутствие нефизических осцилляций (дребезга) на разрывах параметров (условия TVD / ENO / WENO);
  5. **Сходимость невязок:** Итерационный процесс считается сошедшимся только при падении нормы невязок ниже установленного порога (например, $\|R\| / \|R_0\| < 10^{-6}$).
