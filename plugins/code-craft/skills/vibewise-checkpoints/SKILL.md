# Протокол контрольных точек совместной разработки VibeWise

Методология разделяет архитектурное владение (человек принимает ключевые решения) и исполнительскую рутину (модель генерирует проверенный код).

---

## 1. Четыре контрольные точки диалога

```text
Пользовательская задача
       │
       ▼
[1. Build Checkpoint] ────────► Агент спрашивает предпочтительный подход человека,
       │                        анализирует компромиссы (trade-offs) и пограничные случаи.
       ▼
[2. Design Checkpoint] ───────► Согласование архитектуры (структуры таблиц, сигнатур).
       │                        Код НЕ генерируется. Ожидание подтверждения: "Подтверждаю".
       ▼
[3. Implementation Checkpoint]► Перечень затрагиваемых файлов и плана проверок.
       │                        Авторизация: "Реализуй этот шаг".
       ▼
[4. Implementation Report] ───► Отчет: что изменено, как проверено, какие тесты пройдены.
```

---

## 2. Фильтр избыточности HERO (Четыре ловушки агента)

Агенты склонны переусложнять код (Over-defending). Перед предложением решения агент обязан проверить его на 4 ловушки HERO:

1. **H (Hashing / Преждевременное кэширование):**  
   *Ловушка:* Городить кэш в памяти или на диске для операций, которые занимают 10 миллисекунд.  
   *Правило:* Никакого кэширования без подтвержденного замера производительности (профайлинга).
2. **E (Edge cases / Пограничные химеры):**  
   *Ловушка:* Обрабатывать экзотические сценарии с вероятностью $10^{-6}$, загромождая ядро логики десятками вложенных `if`.  
   *Правило:* Обрабатывать только реальные граничные условия текущей постановки.
3. **R (Rubrics / Избыточные классификаторы):**  
   *Ловушка:* Писать сложные многоуровневые системы подсчета баллов или эвристик там, где достаточно одного булева флага или сравнения с константой.
4. **O (Overbuild / Архитектурное раздувание):**  
   *Ловушка:* Создавать фабрики, интерфейсы и абстрактные классы для сущности, существующей в единственном экземпляре.  
   *Правило:* Писать плоский, прямой и читаемый код. Выносить абстракции только при появлении третьей независимой реализации.
