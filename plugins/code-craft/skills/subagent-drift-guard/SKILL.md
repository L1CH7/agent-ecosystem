# Subagent Drift Guard (Семантический аудит)

Используй данный скилл для фонового надзора за ходом выполнения задач сабагентами при долгих расчетах или распределенных исследованиях.

## 1. Регламент активации
- Скилл активируется строго периодически (по нативному cron раз в 5–10 минут) либо при получении промежуточного отчета сабагента.
- **Запрещено** запускать проверку в непрерывном цикле.

## 2. Чек-лист семантического аудита
При пробуждении супервизор проверяет три ключевых маркера:

1. **Workspace Boundary Audit (Проверка рабочего каталога):**
   - В какой директории (`Cwd`) сабагент выполняет команды и читает файлы?
   - *Критерий сбоя:* Агент обращается к локальным файлам в корне мета-репозитория, в то время как задача привязана к подпапке проекта или изолированному `worktree`.
2. **Target Artifact Audit (Проверка целевого артефакта):**
   - Создаются/обновляются ли ожидаемые результирующие файлы задачи?
   - *Критерий сбоя:* Сабагент тратит шаги на бесконечное чтение справочных файлов и логов, не продвигаясь к формированию целевого документа.
3. **Loop Detection (Детекция зацикливания):**
   - Не повторяются ли идентичные вызовы инструментов с одинаковыми аргументами?

## 3. Протокол интервенции при дрифте
Если зафиксировано отклонение от курса:
1. Не убивать сабагента без необходимости, если можно скорректировать курс;
2. Направить через `send_message` жесткую директиву возврата:
   > *«Внимание: зафиксирован дрифт. Ты читаешь файлы в каталоге X, тогда как целевой рабочий каталог — Y. Немедленно переключи фокус на [конкретный путь] и продолжай формирование целевого артефакта»*.
