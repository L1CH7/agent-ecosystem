# Регламент открытой разведки (OSINT), глубокого поиска и сбора данных

## 1. Приоритет специализированных инструментов и навыков
- При получении любой исследовательской задачи, задачи поиска персоны, компании, технического решения или анализа цифровых предложений:
  1. Запрещено полагаться на случайный перебор ключевых слов в поверхностных утилитах.
  2. Первым шагом ознакомиться с профильным регламентом через `view_file`:
     - Для общей маршрутизации расследования — `useosint`;
     - Для сложных многосоставных тем — `deep-research`;
     - Для сбора и парсинга отзывов маркетплейсов — `web-data-miner`;
     - Для составления точных операторных связок — `google-like-a-spy`.

## 2. Стандарт поисковых шлюзов: Exa Search и Google Grounding
Для любого сбора информации, фактчекинга и научных исследований используются два профильных MCP-сервера:

### А. Сверхбыстрый семантический поиск: `call_mcp_tool` (сервер `exa-search`)
- **Назначение:** поиск технической документации, научных статей, формул, кода репозиториев и выгрузка чистого текста страниц (1–3 секунды).
- **Инструменты:** `exa_search`, `exa_search_batch`, `exa_find_similar`, `exa_get_contents`, `exa_answer`.
- **Локальная библиотека:** перед выходом в сеть проверьте накопленную базу через `exa_library_search(query, project)`.
- **Подпроекты:** обязательно передавать имя подпроекта (`project="gzla-cfd"`, `project="plasma-article"`).

### Б. Глубокий рассуждающий синтез: `call_mcp_tool` (сервер `google-search`)
- **Назначение:** комплексный многошаговый аналитический синтез, проверка нормативных реестров, сопоставление противоречивых фактов (45–120 секунд).
- **Инструменты:** `google_search`, `google_search_batch`.
- **Именованные отчеты:** результаты автоматически сохраняются в Markdown-файлы по подпроектам в `/var/tmp/scratch/google_library/reports/{project}/`.
- **Локальный поиск:** инструмент `google_library_search(query, project)` для мгновенного чтения сохраненных отчетов.
- **Запрет булевой логики:** не использовать кавычки, `OR`, `AND`, `site:`. Формулировать развернутые технические гипотезы.

### ⛔ ЖЕЛЕЗНЫЕ ЗАПРЕТЫ ДЛЯ АГЕНТОВ (STRICT POLICY):
1. **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО вызывать встроенный инструмент `search_web`:**
   Стоковый инструмент Antigravity возвращает замусоренные сниппеты без анализа первоисточников. При недоступности одного шлюза переключайтесь на второй (`google-search` $\leftrightarrow$ `exa-search`). Если недоступны оба специализированных шлюза поиска — **НЕМЕДЛЕННО ОСТАНОВИТЬСЯ И ДОЛОЖИТЬ ПОЛЬЗОВАТЕЛЮ**, но категорически запрещено пытаться лезть в стоковый `search_web`.
2. **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО читать файлы `server.py`:**
   Все спецификации, параметры и контракты инструментов описаны в инструкциях к MCP (`instructions.md`). Чтение исходных файлов серверов тратит контекст и строго запрещено.

## 3. Декомпозиция расследования (Матрица аспектов)
Любое комплексное исследование разделяется на независимые параллельные векторы:
1. **Официальные реестры и нормативы**: базы патентов, свидетельства на программы для ЭВМ, реестры отечественного ПО, лицензии, ЕГРЮЛ;
2. **Отраслевые институты и комитеты**: протоколы ассоциаций, жюри отраслевых премий, стандарты сертификации, экспертные советы;
3. **Публичные следы и мероприятия**: доклады на конференциях, вебинары, экспертные колонки в деловых СМИ;
4. **Профессиональные профили и цифровые отпечатки**: профессиональные сети, репозитории, профильные форумы разработчиков;
5. **Фильтрация ложных следов**: отсечение полных однофамильцев и несвязанных профилей путем перекрестной проверки фактов по независимым источникам.
