# Регламент автоматизированного сбора данных (Web Data Mining)

## 1. Приоритет прямого доступа к API
- Перед запуском эмуляции браузера проверить сетевые запросы: открытые REST/JSON интерфейсы работают на порядок быстрее и не подвержены сдвигам верстки.
- Для маркетплейсов на движке Digiseller (Plati, Playerok и др.) выгрузка отзывов выполняется напрямую:
  `GET https://api.digiseller.com/api/reviews?product_id={ID}&rows=100&type=all`

## 2. Архитектура пакетного извлечения
1. **Однократная выгрузка**: Сохранять сырой ответ API или текст страницы во временный файл в `/var/tmp/scratch/<hash>/`.
2. **Семантическая фильтрация**: Прогонять текстовые данные через регулярные выражения или структурированный классификатор.
3. **Сохранение в JSONL/JSON**: Результаты парсинга сохранять с разбивкой по полям:
   - Идентификатор объекта / лота;
   - Дата и автор;
   - Текст отзыва и ответ продавца;
   - Классификация (Jio, Direct, Семья, Брак);
   - Уровень надежности.

## 3. Обработка динамических и защищенных сайтов
- При отсутствии открытого API использовать библиотеки прямого рендеринга (Crawl4AI или Playwright).
- Соблюдать случайные задержки (jitter) и ротацию заголовков User-Agent.
- Обрабатывать ошибки превышения лимитов запросов (HTTP 429) с экспоненциальной задержкой.
