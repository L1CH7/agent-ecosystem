# Git Worktree Orchestrator & Pipelined Integration

Используй данный скилл для координации параллельной работы нескольких агентов над одним репозиторием.

## 1. Изоляция рабочих пространств агентов
При параллельном распределении задач нескольким агентам категорически запрещено работать в одной рабочей директории.
Для каждого воркера создается отдельное изолированное дерево:

```bash
# Создание изолированного worktree на отдельной ветке
git -C <repo_path> worktree add -b agent/<task_id> ../worktrees/<task_id> HEAD
```

### Изоляция окружения тестов:
- Каждый тестовый раннер запускается строго внутри своего каталога `worktree`;
- Порты сетевых служб, имена тестовых баз данных и пути к логам параметризуются идентификатором задачи (`PORT=$((8000 + TASK_ID))`);
- Временные файлы тестов и артефакты изолируются внутри каталога worktree, не задевая основную ветку.

## 2. Конвейерная интеграция (Pipelined Rebase & Merge)
**Категорический запрет Big Bang Merge:** Запрещено одновременно сливать результаты нескольких веток в конце проекта. Слияние выполняет строго Оркестратор/Интегратор по одной ветке:

1. **Воркер завершил задачу:** Прогоняет локальные тесты в своем `worktree` и отправляет отчет Оркестратору.
2. **Шаг интеграции (Оркестратор):**
   - Оркестратор берет первую готовую ветку;
   - Выполняет вливание в основную ветку: `git merge agent/<task_id>`;
   - Запускает быстрый интеграционный смоук-тест.
3. **Обновление параллельных веток (Rebase-on-the-fly):**
   - Следующим готовым воркерам отдается команда обновить свои ветки:
     `git -C ../worktrees/<other_task_id> rebase main`
   - Конфликты разрешаются воркером локально в изолированном дереве.
4. **Очистка (Teardown):**
   - После успешного вливания worktree удаляется:
     ```bash
     git -C <repo_path> worktree remove --force ../worktrees/<task_id>
     git -C <repo_path> branch -D agent/<task_id>
     git -C <repo_path> worktree prune
     ```
